# L'atelier à la volée — épreuve sur papier

Date : 2026-11-17. Suite de `20261117_maquettes.md`. On déroule l'idée sur
de vrais sons du dépôt pour voir comment elle se comporte et où elle casse.
Rien n'est implémenté ; les latences ne sont pas mesurées.

## L'idée en trois phrases

1. **Un nombre est un knob** : `+` `-` `*` `/` et la molette le tirent
   (c'est déjà le cas), une réglette s'affiche dessous avec son nom et ses
   bornes.
2. **Un maillon est un objet texte de vim** (`m`) : `dam` le retire, `cim`
   le remplace, `yam` / `p` le déplacent, `o` / `O` en ouvrent un nouveau.
   La complétion fait entendre chaque proposition.
3. **`&` ouvre l'atelier** pour ce que vim n'a pas : faire bouger un nombre,
   en faire un argument, écouter seul, bifurquer, casque.

Plus de pane de knobs, plus de studio à naviguer : le texte est le graphe.

## Collisions avec vim

| Touche | Dans vim | Verdict |
|---|---|---|
| `a` | append — sert tout le temps | **écartée** |
| `h` `l` pour tirer | déplacement | **écartées** : on garde `+ - * /` et la molette |
| `&` | répète le dernier `:s` | rare ; touche 1 sans Maj en AZERTY |
| `im` / `am` | aucun objet texte `m` | libre |
| `o` / `O` | ouvrir une ligne | **même sens** : c'est vim |
| `Entrée` (normal) | descend d'une ligne, comme `j` | prise pour « maintenant » |
| `]n` `[n` | libres | nombre suivant / précédent |
| `*` `/` sur un nombre | recherche | déjà pris par Ressac *quand le curseur est sur un nombre* seulement |

Déjà pris à vim par Ressac aujourd'hui, à garder en tête : `m` (marques →
muet), `S` (→ scope suivant), `K` (→ fiche), `U` (→ utiliser), `,` et `!`.

## Scénarios

Son d'épreuve, pris dans `plugins/user-synths/arpdriver.jl` :

```julia
@synth :arpdriver (freq=220, sustain=0.12, cutoff=2200) begin
  pulse(:freq, 0.45) |>
  rlpf(:cutoff * (1 + line(2, 0, :sustain)), 0.3) |>
  env_perc(0.001, :sustain)
end
```

**S1 — Tirer `0.45` (largeur de l'impulsion) pendant qu'un arpège joue.**
`0.45` est un littéral : il est cuit dans le SynthDef. Chaque pas refait le
son, qui s'entend à la note suivante. Sur un arpège en doubles croches,
c'est immédiat à l'oreille. Sur un drone, refaire le son coupe la note.
→ Le temps du réglage, Ressac doit compiler un jumeau où le littéral est un
argument (il le fait déjà pour les arguments du `@synth` avec le jumeau
`_drone`), et envoyer des `/ressac/drone/set`. La réglette dit « en
direct ».

**S2 — Tirer le `2` de `line(2, 0, :sustain)`.** Un `line` lit ses bornes
au départ de la note. Même en argument, la note tenue ne bouge pas.
→ La réglette dit « à la prochaine note ». Il faut que le catalogue sache
quels arguments sont lus une seule fois.

**S3 — `cim` sur `rlpf`.** La liste propose `moog_ff`, `bpf`, `rhpf`. Les
arguments ne se correspondent pas tous (`0.3` est une largeur pour l'un, un
gain pour l'autre). L'audit a posé `_remap_args` pour ça. Le premier
argument ici est une expression entière (`:cutoff * (1 + line(…))`) : elle
doit suivre telle quelle.

**S4 — `o` sous `rlpf`, puis on parcourt la complétion.** Chaque
proposition est un son refait et joué. Deux dangers : un maillon instable
qui hurle, et le fait d'imposer ses essais à ce qui joue déjà.
→ L'essai part **au casque** quand une sortie casque existe ; sinon dans la
sortie principale derrière le limiteur déjà en place. `Entrée` garde,
`Échap` rend.

**S5 — `& m` sur `0.3` : le faire bouger.** Le nombre devient
`sin_osc(1) |> range(0.2, 0.4)`, centré sur l'ancienne valeur. Un nombre en
donne trois, chacun un knob. Refait deux fois, la ligne devient illisible.
→ Proposer `& k` (« en faire un argument ») comme l'autre voie : le nombre
sort dans l'en-tête du `@synth`, et c'est *le pattern* qui le fait bouger.
C'est la voie la plus « Ressac ».

**S6 — Le même son joue dans trois slots.** Tout changement les touche
tous. C'est souvent voulu.
→ `& b` bifurque : une copie `arpdriver2`, et la ligne du slot courant est
réécrite pour la jouer.

**S7 — En plein milieu d'une frappe, le texte est faux.** Le son d'avant
continue, la ligne porte `✎`. Rien de neuf : c'est le principe posé pour
les patterns.

**S8 — `u`.** Un geste d'atelier = un `u`. Le son suit l'annulation.

### Là où ça casse

Sur les 44 sons de `plugins/user-synths` :

| Forme | Combien | Atelier |
|---|---|---|
| DSL en pipes | 19 | complet |
| DSL sans pipes (non triés ; au moins un en nœuds, `n1 = ugen(:AllpassC, 400.0, 5.035…)`, la forme qu'exporte l'explorateur) | 7 | nombres oui ; `cim` oui ; `o` ambigu en nœuds (un nœud a plusieurs lecteurs) |
| SuperCollider brut `.scd` | 18 | nombres seulement |

- **40 % des sons sont en `.scd`.** Sans conversion, l'atelier n'y est qu'à
  moitié. `:todsl` existe et refuse proprement ce qu'il ne sait pas lire.
- **La forme en nœuds est illisible** : `5.0350000000000001`, des noms
  `n1…n12`, des arguments sans nom. Deux remèdes en amont : arrondir à
  l'export, et exporter en pipes quand le graphe est une chaîne.
- **Un signal lu deux fois** (`x = bruit(); x |> a` et `x |> b`) est
  recopié, pas partagé : c'est le point F5 de la roadmap (`shared`).
  L'atelier ne doit pas proposer « insérer » là où il dédoublerait un bruit.
- **Le temps de refaire un son** n'est pas mesuré. S'il dépasse la durée
  d'une double croche, parcourir une liste paraîtra mou.

## La sortie casque

Possible côté SuperCollider : SuperDirt démarre aujourd'hui avec toutes ses
orbites sur la sortie 0 (`~dirt.start(57120, 0 ! 12)`). Il faut ouvrir
quatre canaux de sortie et envoyer l'orbite d'essai sur la paire 3-4.

Côté matériel, trois cas :

- une carte à 4 sorties ou plus : direct ;
- deux périphériques (carte + prise casque) : PipeWire ou JACK peuvent
  router les sorties 3-4 de SC vers le second ;
- une seule sortie stéréo : le repli des DJ, principal à gauche, essai à
  droite, en mono.

Dans Ressac : un état de slot de plus (`◖`, « au casque »), une touche pour
basculer un slot entre casque et sortie, et l'atelier qui s'en sert tout
seul pour ses essais.

## La partition au bout des lignes (direction D)

Le moteur sait déjà faire : `pane_notes.jl` interroge les patterns autour
de l'instant courant pour le visualiseur de notes. Ce qui est neuf est le
rendu, une piste par ligne, alignée sur les rangées de l'éditeur.

Cas à trancher :

- un bloc `@dN` sur plusieurs lignes : la piste sur la première ;
- une ligne trop longue : la piste raccourcit (24 colonnes), puis se cache ;
- un pattern plus dense que la piste (`hh*32`) : une densité, pas des coups ;
- un pattern sur plusieurs cycles (`<a b>`, `slow(4)`) : la piste montre le
  cycle courant, `]` `[` élargissent la fenêtre ;
- un drone : une bande dont la hauteur suit le contrôle qui le module.

## À mesurer avant de s'engager

1. Le temps entre une frappe et le son refait audible.
2. Ce que Tachikoma permet pour le fond de ligne qui s'allume et retombe.
3. La police du terminal : `⌒` `↯` `◖` y sont-ils ?
