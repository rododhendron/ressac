## E0.3 — La ligne éclairée : oui

Une cellule Tachikoma est (caractère, style), et le style porte un fond en
vraies couleurs. On peut relire une cellule déjà dessinée par l'éditeur et
la réécrire avec le même caractère, la même couleur de texte et un autre
fond : la coloration syntaxique est gardée.

Mesuré sur un tampon 266×72 : éclairer 12 lignes entières coûte 0,12 ms par
image. `color_lerp`, `pulse` et `breathe` existent pour le fondu.

→ E2.2 se fait comme dessiné : signe **et** fond de ligne.

## E0.4 — Les 18 `.scd` convertis : pas tous justes

Les 18 passent le parseur, mais l'aller-retour (SC → DSL → SC → DSL) n'est
stable que pour 11. Sur les 7 autres, deux ne diffèrent que par des
arguments par défaut rendus explicites (`sin_osc(35.0, 0.0)`) : même son.
Les cinq autres perdent quelque chose :

| Défaut | Fichiers | Effet |
|---|---|---|
| Un bloc `{ … }` devient un nœud vide, rendu `Silent` | aurora, softpad, softchores (`Array.fill(5, { \|i\| Saw.ar(…) })`) | les oscillateurs disparaissent |
| `doneAction: 2` d'un `EnvGen` n'est pas gardé | aurora, silkstring, softpad, softchores | le DSL croit que le son ne se libère pas et ajoute une seconde enveloppe, qui coupe la queue |
| Un signal audio en tête de pipe est enveloppé dans `DC` | plucky | `DC.ar(signal)` fige le signal à sa première valeur |

Le premier contredit la règle posée par l'audit (« le parseur refuse au lieu
de deviner ») : un bloc était « opaque », donc silencieux.

→ E4.1 commence par corriger ces trois points ; l'aller-retour stable sur
les 18 devient son test d'entrée.
